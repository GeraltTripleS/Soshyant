# Soshyant Expert

موتور دستیار تخصصی مستند، با یک دامنه در هر نصب، رابط انگلیسی پیش‌فرض و فارسی، اجرای محلی پیش‌فرض و اتصال اختیاری مدل API.

## Windows desktop launcher

Double-click `Soshyant Expert.exe`, then choose **Open application**. It can start the server without a console and stay in the system tray. If your server is already running in a command window, stop it there first before starting it from the launcher. Administrators now have an **Overview** dashboard; conversations support title search, rename and confirmed deletion. See [DESKTOP.md](DESKTOP.md) for setup, shutdown and update details.

Administrators also have **Watched folders** for approval-based document updates and **Answer review** for missing evidence and user feedback. See [WATCHED-AND-REVIEWS.md](WATCHED-AND-REVIEWS.md). Document/group permissions and private-before-indexing imports are described in [ACCESS-CONTROL.md](ACCESS-CONTROL.md).

## شروع

۱. فایل `START.bat` را اجرا کنید و آدرس نمایش‌داده‌شده را در مرورگر باز کنید.
۲. در اولین اجرا، کد فایل `data/FIRST-ADMIN-CODE.txt` را در صفحه راه‌اندازی وارد کنید و نام کاربری و گذرواژه مدیر را خودتان انتخاب کنید. حساب یا گذرواژه پیش‌فرض وجود ندارد.
۳. در «تنظیم تخصص»، موضوع، محدوده پاسخ، زبان و واژه‌نامه را مشخص کنید.
۴. در «کتابخانه اسناد»، سند اضافه کنید و منتظر وضعیت آماده پاسخ بمانید.
۵. گفت‌وگو بسازید، سؤال بپرسید و با کلیک بر شماره منابع، شاهد را بررسی کنید.

نمونه‌های پوشه `examples` صرفاً آزمایشی و ساختگی‌اند و به صورت خودکار وارد دانش نمی‌شوند.

## قابلیت‌ها

- رابط و پاسخ‌های جدید به صورت پیش‌فرض انگلیسی‌اند. از گزینه Language در ورود یا بالای برنامه، English یا فارسی را انتخاب کنید. انتخاب در همان مرورگر ذخیره می‌شود؛ زبان و جهت رابط بی‌نیاز از بارگذاری مجدد عوض می‌شود و متن اسناد یا پاسخ‌های قبلی ترجمه نمی‌شود.
- انتخاب زبان رابط، زبان پاسخ‌های جدید در همان مرورگر را نیز تعیین می‌کند. مقدار زبان در «تنظیم تخصص» پیش‌فرض درخواست‌های API است که زبان را صریح ارسال نمی‌کنند.

- موتور مستقل از رابط و صوت؛ موضوع با تنظیمات تعیین می‌شود.
- جست‌وجوی ترکیبی واژگانی و معنایی؛ مدل چندزبانه ONNX فقط از مسیر محلی خوانده می‌شود.
- TXT، Markdown، HTML، PDF متنی، DOCX و XLSX؛ اسناد اسکن‌شده به OCR بیرونی نیاز دارند.
- نسخه سند، اولویت منبع، بایگانی قابل بازگشت و حفظ فایل نسخه قبلی.
- ذخیره یکپارچه سند و شواهد در تراکنش SQLite؛ انتشار ناقص نمایه انجام نمی‌شود.
- پاسخ ساخت‌یافته: answered، clarify یا insufficient، با نسخه دانش و ارجاع‌ها.
- کنترل قرارداد ارجاع‌ها؛ صحت معنایی همه ادعاها همچنان نیازمند ارزیابی متخصص است.
- مدیر و کاربر، گذرواژه هش‌شده، نشست سمت سرور، کنترل نقش و جداسازی گفت‌وگوها.
- صف محدود برای پاسخ و ورود سند، لغو درخواست و اعلام خطا؛ یک درخواست مدل در هر لحظه برای سخت‌افزار کوچک.
- بازخورد، کپی و دریافت گفت‌وگو، پشتیبان‌گیری و ابزار بازیابی آفلاین.
- فایل‌های رابط محلی‌اند؛ CDN، فونت اینترنتی یا دانلود خودکار وجود ندارد. مدل API فقط پس از انتخاب و تأیید صریح مدیر با ارائه‌دهنده ارتباط می‌گیرد.

## اجرای مستقل

این پوشه شامل Python مستقل در `runtime`، وابستگی‌های استخراج و جست‌وجو، یک مدل زبانی محلی در `assets/model.gguf` و ابزار llama.cpp است. در اجرای عادی به پوشه پروژه قبلی وابسته نیست.

مدل زبانی از نسخه موجود Bonsai-2-27B تهیه شده است. مدل جست‌وجو از `Qdrant/paraphrase-multilingual-MiniLM-L12-v2-onnx-Q` است؛ بازبینی و منشأ آن در `assets/embeddings/provenance.json` ثبت می‌شود. فایل `assets-manifest.json` صحت دارایی‌های بسته را ثبت می‌کند. شرایط مدل‌ها و وابستگی‌ها مستقل از کد برنامه‌اند؛ این بسته مجوز تجاری جدیدی برای آن‌ها ایجاد نمی‌کند.

`CHECK-INSTALL.bat` وجود دارایی‌ها، صحت فایل‌ها و اجرای مدل جست‌وجو را بررسی می‌کند. مدل زبانی هنگام اولین پرسش دارای شاهد بارگذاری می‌شود؛ بنابراین اولین پاسخ کندتر است. اگر حافظه GPU کافی نیست، مقدار `gpu_layers` در `config/server.json` را کم کنید؛ صفر برای CPU است. تغییر پیکربندی سرور نیاز به راه‌اندازی مجدد دارد.

`tools/prepare_local.py` ابزار آماده‌سازی توسعه‌دهنده است و ممکن است با گزینه صریح دانلود از اینترنت استفاده کند. این ابزار در شروع عادی برنامه اجرا نمی‌شود. روی سرور جدا از اینترنت، کل پوشه آماده‌شده را منتقل کنید؛ نصب‌کننده اینترنتی اجرا نکنید.

## شبکه داخلی

حالت پیش‌فرض فقط روی خود سرور قابل دسترسی است. برای دسترسی شبکه، مدیر شبکه باید گواهی TLS معتبر و مورد اعتماد کاربران، کلید خصوصی و نام یا IP مجاز را فراهم کند:

```powershell
runtime\python.exe start.py --host 0.0.0.0 --cert C:\certs\server.crt --key C:\certs\server.key --allowed-host expert.internal
```

نام مجاز باید با نام گواهی و آدرسی که کاربران باز می‌کنند منطبق باشد. ابزار برنامه تنظیمات فایروال، گواهی مورد اعتماد یا مجوز سیستم را خودکار تغییر نمی‌دهد. مدل زبانی همیشه فقط روی loopback اجرا می‌شود.

کاربران عادی منابع فعال همین سازمان را می‌بینند، اما گفت‌وگوهای یکدیگر را نمی‌بینند. این نسخه برای یک سازمان و یک مجموعه دانش مشترک است؛ کنترل دسترسی متفاوت برای تک‌تک اسناد در محدوده این نسخه نیست.

## نگهداری و بازیابی

`BACKUP.bat` یا بخش نگهداری رابط، بسته پشتیبان اسناد، گفت‌وگوها، حساب‌ها و تنظیم تخصص را می‌سازد. مدل‌ها و Python در پشتیبان داده نیستند و باید همراه بسته برنامه نگهداری شوند. داده و پشتیبان به شکل رمزگذاری‌نشده روی دیسک ذخیره می‌شوند؛ نگهداری و دسترسی فایل‌ها باید مطابق سیاست مجموعه انجام شود. برنامه به صورت پیش‌فرض متن پرسش و سند را در لاگ HTTP ثبت نمی‌کند؛ این داده‌ها برای کارکرد محصول در پایگاه داده محلی ذخیره می‌شوند.

برای بازیابی، ابتدا سرور را متوقف کنید و اجرا کنید:

```powershell
runtime\python.exe manage.py restore data\backups\backup-NAME.zip
```

ابزار فرمت و صحت پشتیبان را بررسی می‌کند، نسخه فعلی را قبل از جایگزینی حفظ می‌کند و نشست‌های قبلی را لغو می‌کند. گذرواژه‌ها از پشتیبان بازیابی می‌شوند. برای ارتقای آفلاین، سرور را متوقف کنید، پشتیبان بگیرید و تنها کد و دارایی‌های نسخه جدید را از بسته معتبر جایگزین کنید؛ پوشه `data` و تنظیمات مشتری حفظ شوند. مهاجرت خودکار میان نسخه‌های آینده هنوز تعریف نشده است.

## API داخلی

مستند کامل مسیرها در `API.md` است. تمام مسیرهای عملیاتی ورود کاربر می‌خواهند و تغییرات به CSRF token نشست نیاز دارند. هویت کاربر از نشست سرور گرفته می‌شود؛ شناسه گفت‌وگوی ارسالی به تنهایی مجوز دسترسی نیست.

## آزمون

```powershell
runtime\python.exe -m unittest discover -s tests -v
runtime\python.exe manage.py check --full
runtime\python.exe tools\smoke_real.py
```

آزمون‌های واحد از اسناد موقت و مدل شبیه‌سازی‌شده استفاده می‌کنند. آزمون آخر مدل واقعی را روی داده آزمایشی موقت اجرا و فقط پردازش مدل خودش را متوقف می‌کند. اسناد مشتری وارد آن نمی‌شوند.

## حدود اعتبارسنجی

این نسخه محلی قابل اجراست؛ تأیید تخصص در هر موضوع نیاز به مجموعه پرسش‌های بررسی‌شده توسط متخصص دارد. افزودن سند به معنی آموزش وزن مدل نیست. فارسی‌بودن رابط به معنی تأیید کیفیت همه پاسخ‌های فارسی نیست. مدل چندزبانه و مدل زبانی باید روی زبان و دامنه مشتری ارزیابی شوند. آزمون دستگاه تمیز، قطع واقعی اینترنت، گواهی شبکه داخلی و ظرفیت هم‌زمان روی سخت‌افزار مشتری جداگانه انجام می‌شوند؛ از روی وجود فایل‌ها ادعای قبولی آن‌ها نمی‌شود.

## ماشین‌حساب سخت‌افزار

گزینه **Hardware planner** در منو، با انتخاب مدل، تعداد کاربران هم‌زمان، درصد فعالیت، ظرفیت متن و حافظه هر GPU، تعداد کارت و برآورد رم و هسته فیزیکی پردازنده را نمایش می‌دهد. پنج پروفایل محلی Bonsai و Qwen3 در اندازه‌های 4B، 8B، 14B و 32B موجود است؛ فقط مدل Bonsai همراه این نصب قرار دارد. انتخاب پروفایل دیگر مدل را دانلود یا فعال نمی‌کند.

محاسبات بدون اینترنت کار می‌کنند. تعداد GPU بدون آزمون سرعت فقط برآورد حافظه است؛ برای برآورد سرعت، نتیجه اندازه‌گیری همان مدل و سخت‌افزار لازم است. رم و پردازنده پیشنهاد اولیه مهندسی هستند. جزئیات فرض‌ها و منابع در [CAPACITY.md](CAPACITY.md) آمده است. برنامه فعلی همچنان یک پاسخ را در لحظه پردازش می‌کند؛ خروجی ماشین‌حساب، استقرار چند GPU یا پردازش موازی را فعال نمی‌کند.

## انتخاب مدل واقعی و ورود پوشه

در بخش **Language models** یک پنل واحد برای انتخاب پوشه، شناسایی مدل‌ها، انتخاب از منو و فعال‌سازی قرار دارد. با **Choose folder…** پوشه را از هر درایو محلی سرور انتخاب کنید و **Use this folder & scan** را بزنید. همچنین می‌توانید مسیر پوشه را بنویسید و **Scan folder** را بزنید. فایل‌های GGUF معتبر، همراه زیرپوشه‌ها در صورت انتخاب، شناسایی می‌شوند و نتیجه کنار همان کنترل‌ها نمایش داده می‌شود. فایل‌ها جابه‌جا یا دانلود نمی‌شوند. سپس مدل را انتخاب و **Activate selected model** را بزنید؛ انتخاب فقط پس از بارگذاری موفق ذخیره می‌شود.

در **Documents → Add a document folder** اسناد را گروهی وارد کنید. برای حذف سند بایگانی‌شده **Show archived** را روشن و **Delete permanently** را انتخاب کنید؛ تأیید لازم است. جزئیات در [MODELS-AND-FOLDERS.md](MODELS-AND-FOLDERS.md) آمده است.


## مدل با کلید API

در همان پنل **Language models**، گزینه **Add an API model** را باز کنید. نام اتصال، ارائه‌دهنده، شناسه مدل و کلید API را وارد و **Save API model** را بزنید؛ سرویس OpenAI و APIهای سازگار با Chat Completions پشتیبانی می‌شوند. برای سرویس سازگار، نشانی پایه HTTPS را هم وارد کنید. اتصال در همان منوی مدل‌ها ظاهر می‌شود و برای فعال‌سازی باید ارسال اطلاعات به ارائه‌دهنده را صریحاً تأیید کنید.

کلید فقط در سرور ذخیره می‌شود و در ویندوز برای حساب اجرای سرور رمزگذاری می‌شود. اسناد و جست‌وجو محلی می‌مانند، اما هنگام استفاده از مدل API، پرسش، شاهدهای بازیابی‌شده، تنظیمات دامنه و سابقه اخیر گفت‌وگو به ارائه‌دهنده ارسال می‌شوند. این حالت به اینترنت نیاز دارد. جزئیات، محدودیت‌ها و منابع رسمی در [CLOUD-MODELS.md](CLOUD-MODELS.md) است. هیچ کلید واقعی یا سندی در آزمون‌های توسعه به سرویس بیرونی ارسال نشد.


## برنامه اندروید

پروژه بومی اندروید در پوشه مجاور `Soshyant Android` قرار دارد. فایل APK، گواهی عمومی سرور و راهنمای اتصال در پوشه `dist` آن آماده‌اند. گوشی از طریق درگاه HTTPS وای‌فای به API همین سرور وصل می‌شود؛ مدل روی گوشی اجرا نمی‌شود. راه‌انداز `START-WIFI.bat` درگاه را اجرا می‌کند و نشانی دسکتاپ را تغییر نمی‌دهد. راهنمای کامل در README پروژه اندروید است.
