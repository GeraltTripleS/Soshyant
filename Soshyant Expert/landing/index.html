      Why RAG — not fine-tuning?

      A

      Documents change. Answers follow.

      fine-tune: retrain the modelrag: re-index the changed file

      Update a manual and answers use the new version as soon as it’s re-indexed.

      B

      Knowledge is data, not weights.

      fine-tune: baked into weightsrag: versioned records you control

      Your content stays in a database on your server — versioned and backed up like any business record.

      C

      Citations need sources.

      fine-tune: can’t point to a sourcerag: every claim → a passage

      Answers point at real passages — document, section and version — so people can check them.

      08 // Query log

      Questions, answered.

      Something else on your mind? Open a channel — we’re happy to go deep.

      Q.01What does “RAG” mean here?
      A ›

      Retrieval-augmented generation. When someone asks a question, Soshyant first searches your indexed documents (keyword and semantic), keeps only the passages that person is allowed to see, and hands them to the language model with instructions to answer only from that evidence and cite it. If the passages don’t support an answer, it says so.

      Q.02Does it train the model on our documents?
      A ›

      No. Documents are indexed for retrieval; the model’s weights are never changed. When you update a document, answers use the new version as soon as it’s re-indexed — no retraining.

      Q.03Does it need an internet connection?
      A ›

      Not in local mode. The language model, the embedding model and the interface files all load from the server’s own disk — no CDN, web fonts or automatic downloads. If an administrator chooses to connect a cloud model, the server then needs internet and the question plus retrieved passages go to that provider — only after explicit approval.

      Q.04Which documents can it read?
      A ›

      PDF (with a text layer), Word (DOCX), Excel (XLSX), plain text, Markdown and HTML. Scanned documents need OCR before import. Upload files one by one, import a folder, or watch a folder for changes.

      Q.05Which languages are supported?
      A ›

      The interface and answers are available in English and Persian (فارسی), with a full right-to-left layout. We recommend validating answer quality on real questions from your own domain and language during a pilot.

      Q.06Can different teams see different documents?
      A ›

      Yes. Administrators create access groups and choose which groups can use each document. Restricted passages are filtered on the server before ranking and before anything reaches the model. Confidential files can be imported as “administrators only” from the first second.

      Q.07What hardware do we need?
      A ›

      A single Windows server or workstation. A GPU is recommended for responsive answers; CPU-only operation is possible. The built-in hardware planner estimates GPUs, RAM and CPU cores for your number of users — and we’ll size it with you during the demo.

      Q.08Is there a mobile app?
      A ›

      Yes — a native Android app that connects to your own server over Wi-Fi using HTTPS and your private certificate. The model never runs on the phone, passwords aren’t stored on it, and screenshots are blocked.

      Q.09Where is our data stored?
      A ›

      Documents, conversations and accounts live in a local database on your server, and backups are written there too. You decide how that storage is protected and retained under your own policies.
